# 新エンジンの現状評価とShadow初回リリース

2026-10-11。今回のサイクルは「発走前の確定保存」と「確定結果との照合」の2項目。旧エンジンとのHybrid、実購入接続、既存Viewer変更は行わない。現在の本番エンジンは `keiba_predict_tool.py` のまま。

## 事実・評価・未確認の区別

- **コード上の事実**：以下の構造・列・条件・学習パラメータは実装から確認した。
- **実測**：既存の隔離比較と今回の同一レース比較。2025／2026年は既に参照した開発期間で、未知期間ではない。
- **未確認**：古い原始情報がそのレースの発走前に取得されていたこと。日付を遡って計算できることと、取得時点が検証済みであることは異なる。

今回の過去比較は取得時刻の不明なアーカイブを含む**探索診断**。依頼の「各時点で取得可能な情報だけ」の厳格な過去検証はまだ完成していない。発走後取得の証拠がある調教・厩舎評価は既存ゲートで不使用にするが、U指数・乗り替わり・凄馬等の古い全入力の時刻を検証できていない。これらを検証済みと説明したり、当日の予測で古い結果を使うことはしない。最初の評価資料は本日発走前に保存したShadowから蓄積する。

## 学習条件

- 馬モデル：2021-01-01〜2024-12-31、確定・6頭以上。2020年は履歴。2022・2023・2024年のOOFはそれ以前の年度だけで生成。
- 基礎HistGB：深さ3、100反復、学習率0.06、最小葉80、L2=10、早期終了なし、乱数17。新しい年を重くする重みは半減期365日・下限0.25。
- 補正：群ごと標準化、観測20以上かつ非定数のみ。欠損は中立。L2=0.001、最適化最大150反復、未収束はエラー。
- 候補群：基礎top3＋上限付き補正。条件付き着順用のOOFでは、当該年度で補正を学習せず、前年度までのOOFだけで補正する。
- 着順HistGB：深さ2／最大4葉、100反復、最小葉120、学習率0.06、L2=10、早期終了なし。相対順位・shareは着順が既知の3頭だけではなく全出馬で計算。
- 群：最大18頭の全3頭組。所属確率から `p/(1-p)` の積で群質量を作る。独立事前分布をちょうど3頭に条件付けた仮定で、相関まで直接学習した群モデルではない。
- 着順：馬ごとの条件付き1／2／3着確率の積を各群の6順列内で正規化。群の質量×順列の条件付き確率が3連単の同時確率。
- キャッシュ：学習行の内容・コード・依存版・期間を記録。出力列の追加だけでは馬のモデルを再学習しない。予測用コード版はモデルSHAと別にモデル版へ含める。

## STEP 2：新旧比較と不足

今回の比較は旧アーカイブと同一出馬で、2025年平場・新馬以外・6頭以上2,586レース、2026年2,064レース。旧の不正順位／不完全レースは丸ごと除外。旧の「主軸」は保存順位1位（◉を含む）。新は独立の読み出しで、3着内候補の中から勝率最大を主軸、2着確率最大を次軸、残りを3着内率で並べる。旧の爆／飛／補正を加えない。

「印順上位3頭の捕捉」はその3頭が実際の1〜3着馬を何頭含むか／3。「群上位3頭」は3着内確率の高い3頭で、印順とは区別して保存する。

印順の主軸候補池は3着内率0.35以上の頭数を参考に3〜6頭へ制限する初期ルール。閾値自体の優位は未検証で、同時確率の上位買い目を生成する分布にはこの池を使わない。馬の周辺確率・群順位・印順・馬券候補を混同しない。

3連複は上位5頭BOX10点、最初の2点を200円・他100円で1,200円。3連単は上位2頭の1／2着入替＋次3頭を3着、6点×200円で1,200円。どの方式も同一レース・券種別同一点数・同じ単価規則・同じ投資額（2026年各2,476,800円）。選別を加えない診断で、全レース購入の提案ではない。

候補選択に馬券オッズを使用しない。全モデルを同じ公式100円払戻で精算しており、単勝オッズを3連単・3連複の価格に代用しない。現行Auto R／重賞Hybridでも、本日Shadowの同時確率上位12候補でもない。購入ロジックの最適化と予測精度を分けるための固定レシピである。

新候補群の2025年は主軸勝率28.27％／3着内58.78％、上位3頭捕捉47.53％、3連複71.04％、3連単65.98％。旧は26.57％／56.03％、捕捉47.19％、3連複80.98％、3連単79.18％。両年度とも回収では未達。**Brier改善を捕捉・勝ち軸・利益の改善と置き換えて説明しない。**

旧と候補群で主軸が違う2,745レースを記録。`different_race_features.csv` と `new_group_factor_differences.csv` に特徴量と新の主要因子を出力した。新の補正群は合計上限後の寄与を按分する。基礎因子は学習期間中央値へ置き換えたロジット差で、足し算できるSHAPや因果効果ではない。旧の当時の学習済みモデル・特徴量版が十分残っておらず、旧側の厳密な因子寄与は未復元。

比較に必要な不足：

1. 旧側も同じ発走前時刻に確定保存した出馬・モデル版・確率。旧の運用CSVをあとから読むだけでは直前状態を保証できない。
2. 過去U指数・凄馬・乗り換え等の取得時点。取得後に更新された情報を過去に持っていたと仮定しない。
3. 候補群だけ／着順だけ／正規化だけのアブレーション。Brier改善の源泉を分解する。
4. 同時確率上位の馬券候補に対する校正・券種別評価。ライブ馬券オッズを使う場合は同一時刻・同じ価格ソースを保存する。
5. 日別ブートストラップ、頭数・コース・距離・人気帯での悪化、完全未使用期間。最良条件の後付け採用をしない。

## STEP 4：実装した最小Shadow

```sh
./.venv314/bin/python -m analysis_engine.shadow_predict --date 20261011
```

独立した `outputs/shadow_engine/YYYYMMDD/時刻_一意ID/` へ毎回新規保存する。過去日に時刻を遡らせる実行は拒否。開始済み・発走時刻不明／不一致・3〜18頭以外は出力しない。計算終了時とファイル保存時に開始時刻を再確認し、期限を過ぎたレースは除く。2秒の余裕を設ける。

|ファイル|内容|
|---|---|
|`input_index.csv`|読み込んだIndexの実バイト列。ローカル取得時刻とSHAを記録|
|`horses.csv`|勝率、2着ちょうど、3着内率、印順、候補群順位、印、発走・予測時刻、取得時刻の状態、モデル版|
|`candidates.csv`|3連複の3頭組／3連単の順番、各上位12候補と同時確率。100円は理論比較の単価で、購入予定ではない|
|`explanations.csv`|基礎の中央値置換差、上限後の補正群寄与、主要5因子と説明方法|
|`race_eligibility.csv`|全レースの時刻チェックと除外理由|
|`manifest.json`|確定保存時刻、入力・全CSVのSHA、モデル・特徴量の版、学習条件、依存版、制約、時間、購入非接続|

Index全体の本来のスクレイピング取得時刻は不明なら空欄。ファイルmtimeを取得時刻として捏造しない。今回のローカル捕捉時刻が発走前であることは検証できる。調教・厩舎・血統・オッズ等に個別取得時刻があれば馬キーで紐付けて残す。調教／厩舎の未来時刻や不明時刻は当日補正へ入れない。

発走前の単勝オッズ・実人気も評価用に保存するが、予測入力・買い目期待値には使用しない。取得時刻確認済みの人気6位以下に限定した好走・群上位5頭捕捉を結果照合時に集計できる。

結果照合：

```sh
./.venv314/bin/python -m analysis_engine.shadow_score --forecast outputs/shadow_engine/20261011/080000_430151_40180d6f
```

上記は保存先の例。予測実行が表示する出力先を指定する。日付対応の既存Resultsを読み、元予測のSHAを検証し、`evaluations/` へ新規保存する。入力結果も捕捉してSHAと実取得時刻を記録。未開始・結果欠落・頭数変更・不完全着順・同着は未評価として残す。同着の複数払戻精算は今回の最小構成では未対応。確定予測は再生成・上書きしない。

MVPは手動実行で開始済み。既存自動処理や定期実行へは登録していない。結果自動収集の更新後、同じ保存予測を照合できる。本日24レース344頭・候補576行の発走前保存に成功。初回07:48 JST、追加検証の保存も発走前。本日実績はまだ0、24レース未評価である。

## 計算時間とボトルネック

今回の単独Shadow初回は18.13秒（データ基盤初回、説明と同時確率候補を含む）。既存データ・特徴量を再利用してモデル学習する実行は約4秒、モデルも再利用した最終コードの実行は1.72秒。24レース344頭。モデル再利用でも入力SHA・予測時刻・開始時刻チェックを省略しない。

前回測定の同じ24レース315頭・同じ2021〜2024学習・CSVまでの比較では、旧116.10秒／再利用27.19秒、新3方式＋候補群＋フォーカス27.33秒／3.21秒。今回の単独Shadowと範囲・対象日が違うため、その数字同士の速度倍率は出さない。収集・WIN5・HTML・購入はどちらも測定外。旧と機能はまだ同等ではない。

初回の重い箇所はParquet変換と全履歴の特徴量集計。馬の学習自体は数秒。マスター更新で全スナップショットを作り直す点が今後のボトルネック。全年度の診断ループと毎日の予測時間も区別する。

## テスト・影響・次のサイクル

新エンジン33テスト、既存購入の重賞Hybrid8テスト・少頭数選別9テストが成功。候補同時分布と馬の周辺確率の一致、入力に結果列を足しても予測が変わらないこと、欠損／不一致時刻の除外、確定保存後の上書き拒否、結果欠落の保留、意図的重ね買いの単価付き精算、取得時刻の馬キー結合を確認した。

独立検算でキャッシュ前後の確率・順位・候補一致、確率和、全CSVのSHA、券面・単価・日別同一点数・同額投資・払戻を確認。旧予測コード、既存購入コード・設定のSHAは初回と一致。既存プロセスの再起動、予約変更、認証操作、実投票は行っていない。

次の優先3項目：

1. **候補群の捕捉と低人気好走**：Brier改善に対して上位群捕捉が小さい原因を、正規化だけの効果と特徴量による識別へ分解。上位3／5頭、取り漏れ馬、頭数・馬場・距離・人気別で評価。
2. **条件付き着順と同時確率候補**：順位側のアブレーション、同時確率の校正、上位候補への投資集中を同額で比較。少頭数＋強い勝ち軸の仮説を過去の別期間で設定し、その後の未使用期間で検証。
3. **取得時刻と血統の個別検証**：Shadowの時刻証拠を蓄積し、父／母父と条件相性を別々に除外して安定性を確認。調教・厩舎評価は証拠と母数が増えてから学習。取得不明の特徴を有効と扱わない。
