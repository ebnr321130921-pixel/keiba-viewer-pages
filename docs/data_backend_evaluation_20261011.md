# データ基盤の実測と改善案（2026-10-11）

Pythonは既に3.14.4で、通常の4つの起動ファイルも `.venv314/bin/python` に統一されている。
今回の優先はPythonの再更新ではなく、分析時の全CSV走査、過去集計、キャッシュの再利用を改善すること。

## 実測

`master_merged_analysis.csv` は717,038,391バイト、248列、309,490行。
父・母・母父、日付・競馬場・R・馬番、距離、着順の9列を取り出し、2025年の父×母父×競馬場×距離の出走数・3着内数を比較した。

|処理|3回の中央値|
|---|---:|
|CSVから必要列をpandasで読む・集計する|1.97224秒|
|CSVをDuckDBで読む・集計する|0.66583秒|
|投影ParquetをDuckDBで読む・集計する|0.00935秒|

このクエリではParquet版がpandas版の約211分の1の時間。初回変換は0.693秒、投影Parquetは1,864,820バイト。
元の248列と9列の投影は同じ保存範囲ではないため、ファイルサイズの比率をマスター全体の圧縮率としては扱わない。
反復実行のローカル実測で、OSのキャッシュが温まっている。予測全体・全列読込・学習の改善倍率ではない。
Parquetの必要列・条件だけを読む仕組みは [DuckDBの公式説明](https://duckdb.org/docs/current/guides/file_formats/query_parquet) を参照。

独立照合で309,490行×9列の全値がCSVと一致し、日付・競馬場・R・馬番の重複もなかった。
各3回の集計結果32,029組も一致。元CSVのSHAと更新時刻は実行前後で一致した。
CSVは区切り・引用符を明示して読み込んだ。自動推定では初期行に引用符が現れず、後半の引用されたJSON列を誤解析したため、読み飛ばしで回避してはいない。

## 速くする対象を分ける

既存の2026-10-10のログでは、マスター読込・脚質履歴は既にキャッシュ時0.45〜0.46秒。
学習キャッシュがない実行は学習204.26秒、一日処理230.24秒。学習キャッシュを使う実行は学習0.11秒、一日処理25.88秒。
これは以前のログの計測で、今回のParquet実験と同じ条件の比較ではない。
Parquetだけで204秒の学習を消せるわけではない。分析用走査と特徴量生成を先に最適化し、学習は別途プロファイルする。
記録：[初回ログ](../outputs/prediction_method_audit_20261010/training_cache_first.log)、[再利用ログ](../outputs/prediction_method_audit_20261010/training_cache_second.log)。

`keiba_predict_tool.py` の共有学習キャッシュは現在3件保持。
複数年度の再計算が並行すると互いのキャッシュを追い出す余地があるため、年・学習期間ごとの保持を検討する。
ただし入力・ラベル・モデルレシピ・依存バージョンを含む `training_identity()` の内容比較は維持する。単にキャッシュ判定を緩めて速くしてはいけない。
実際に追い出しが再学習を増やしたかは、次の実ジョブのログで確認する。

## 導入順

1. **分析用データ層**：元CSVを正本として残し、Index・Results・Predict・血統情報を用途別にParquetへ変換する。最初は年単位で整理し、小さい日別ファイルを無制限に増やさない。
2. **DuckDB集計**：列・期間を限定した走査、キーによる結合、血統・騎手・厩舎などの過去集計を実装する。データ量と同時ジョブに合わせてスレッド数・メモリを制限する。
3. **増分更新と履歴**：入力SHA・スキーマ版・生成日時・取得日時・モデル版をmanifestへ保存し、変更された期間だけ再生成する。書き込み担当は一つにし、検査済みのファイル集合を読者へ公開する。
4. **予測への接続**：CSVとParquetから同じ特徴量を作り、馬番・値・欠損・印・買い目まで一致することを確認してから読込経路を置換する。購入パネルの鮮度比較も引き続き有効にする。

型は明示する。レース・馬のIDは文字列、日付と時刻は形式・JSTを統一、数値の欠損はNULLとして扱う。
取得できなかった情報と評価が低い情報を別に保持し、CSVごとの列追加にもスキーマ版で対応する。
SQLは日付や値のパラメータを使い、読込エラーの無視や不正行の自動除外で件数を合わせない。
バックエンド変更はモデル変更と同じ日にまとめず、速度と精度への影響をそれぞれ評価する。

## 血統を予測へ入れる方法

父は2020〜2026年のマスターでほぼ全行に存在する。ただし過去の各時点で取得済みだったことは、この実験では保証していない。
今回の父×母父×競馬場×距離の2025年集計は32,029組あり、23,106組が1出走、98.54%が5出走未満、20出走以上は0組だった。
細分化を強くするほど適性を見分けやすくなるとは限らない。

- 父と母父をまず別々に扱い、芝/ダート・距離帯など広い条件から始める。母の直接カテゴリや細かな交差を大量に投入しない。
- 対象日より前の累積出走・勝利・3着内数を集計する。同日結果も購入時に未確定のものは入れない。
- 成績を全体・芝ダート・距離帯の基準へ寄せ、実出走数・異なる産駒数を信頼度として持つ。少標本なら補正を中立に近づける。
- 種牡馬の単純な高勝率を強さと決めず、現行の能力・市場評価で説明できる部分に対する追加効果を検証する。厩舎・騎手・強い産駒1頭の繰り返しによる偏りも確認する。
- 現行モデル、父のみ、母父のみ、両方の4条件を時系列で比較する。確率の校正、◎/○の複勝率、爆/飛、同じ選別・買い目での回収率まで確認する。
- 補正幅や対象条件を過去の高配当へ合わせて固定しない。独立した後続期間で効果が続くことを見て採用する。

現在のML特徴量の明示リストには父・母父は含まれていない。この資料は導入案であり、血統補正を本番へ反映したものではない。
