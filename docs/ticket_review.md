# 買い目精査・コード整理（2026-10-03）

## 今回反映したもの

- 購入側のフォーメーション展開を `data_view.formation_tickets` に統一。
- 生成時・ブラウザ入力前に、券種、3列と券の一致、点数、行内重複、正の100円単位の単価を検査。不一致は停止。
- 買い目JSONの `ticket_audit` に口数、券の種類数、重複口数・金額、最大券別購入額を追加。購入行をまたぐ重複は意図した別口として保持。
- 全空欄の爆印・飛印や数値の予測順位をViewerの文字列で更新する際、pandas 3で失敗する型不整合を修正。
- リポジトリ内で参照されていない `resolve_mode`、単一行用 `load_formation_pattern`、`build_recommend_pack_dir` を削除。複数行対応の現行処理は残す。

購入馬・特殊印の優先順・単価・構成は変更していない。Kaimeは統合実行が `--enable-output` を付けて実行し、購入側もRecommendのランクを参照するため、ファイル全体は削除していない。過去CSV・購入履歴は削除していない。

## 重複の実態

|構成|購入口数|券の種類数|重複口数|重複分の金額|投資総額|
|---|---:|---:|---:|---:|---:|
|研究用固定95点（3連複88＋3連単7）|95|56|39|3,900円|9,500円|
|現行設定B102|102|63|39|3,900円|10,200円|
|現行設定K109|65|49|16|3,200円|10,900円|

B/Kは18頭の合成データで現行Excelを展開した構成確認。実投票ではない。重複分の金額は行順で最初の1口を除いた分。券種が違う券や3連単の着順違いは別の券として数える。

## 固定95点の重複を1口ずつにした理論比較

保存予測の順位を固定し、`calibrate_style_vote_string.load_rows` / `prepare_races` / `tickets` を使用。2026-06-01～09-27、全出走馬の保存行が結果との結合後も残り、予測順位が1～頭数で連続、確定1～3着と払戻がある9頭以上のレースのみ。実払戻を使用し、結果は選別入力にしない。

|期間|レース数|元の95口・9,500円の回収率|重複を1口化した56口・5,600円の回収率|追加重複39口だけの回収率|
|---|---:|---:|---:|---:|
|2026年6～7月|443|60.70%|61.87%|59.02%|
|2026年8月|285|81.59%|78.71%|85.71%|
|2026年9月1～27日|188|67.68%|69.58%|64.97%|

券の対象範囲は同じなので的中レースは変わらず、賭け金と払戻の厚みだけが変わる。8月は重複を削ると回収率が悪化し、全期間で一律削除が良いとは言えない。支出が違うため利益額の改善だけで優劣を決めない。

保存予測の再生成・実行時刻・モデル方式の来歴が完全ではなく、既に探索した期間でもある。現行B/Kの特殊印・Viewer順の購入実績や、未使用期間での改善証明ではない。重複削除、購入モード・予算の変更は未採用。

次の検証対象は、現行Viewer順の買い目単位での重複投資効果、同じ総予算での配分比較、実券種オッズを取得した場合の期待値判定。収益枠・エンタメ枠は成績を分ける。
