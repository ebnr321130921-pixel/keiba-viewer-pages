# Indexの血統・厩舎評価・調教詳細

2026-10-03。通常の `umanity_collect_daily_uindex_and_results.py` に統合。
Indexへ30列を追加し、通常マージでも `(Index)` 列として保持する。
夜間の `collect_umanity_supplemental.py` も同じ取得・検証・保存処理を使用。
他人の予測や厩舎コメントはIndexに入れない。実オッズの定期記録は従来の通常収集が担当する。
「みんなの人気」は通常収集の取得・CSV出力から除外した。既存CSVの旧列は一括削除しないが、予測・補正・妙味診断の入力には使わない。
市場入力は実オッズと対応するJST取得時刻があり、取得が予定発走前と確認できる場合のみ採用する。実オッズ未取得、時刻不明、発走後取得は欠損扱いとし、確定オッズや旧列で補わない。

## 内容と再取得

|種類|追加する値|通常の再取得|
|---|---|---|
|血統|父・母・母父・兄姉・血統馬ID|同一レースで取得成功したら不要|
|厩舎評価|◎・○・△等の評価、元画像名|発走前は最長1時間キャッシュ。発走前に取得できた値は発走後保持|
|調教|最新調教日・騎手・コース・強度・採点・6F〜1F|同一レースで取得成功したら不要|

全種類に取得時刻(JST)・取得元・発走前取得(1/0)・取得状態を付ける。
出走馬集合や馬名が変わった場合、取得に失敗した場合、明示的に再取得を指定した場合は再確認する。
取得済みデータの再利用にはIndexの値・取得時刻・取得状態を使う。
`IndexExtras` や自動バックアップは作らない。正規のIndex/Merged CSVだけに結果を保存する。
調教は元HTMLの6F〜1Fの区切りを保ち、途中の2F欠損で他の時計をずらさない。
「モヤで見えず」は欠損、「中間軽めに乗られる」は時計のない備考として扱う。欠損は0秒ではない。
時計がない馬も行から消さず「取得済み:時計未掲載:v2」と記録する。
未対応の時計形式は「未取得:時計形式未対応」と明記し、他馬の時計を巻き添えにしない。
開催日より後の調教は拒否する。
旧解析の調教値にはv2の印がないため、血統を再取得せず調教だけ取り直す。

厩舎画像の対応は実ページと画像で確認済み。

|画像|評価|
|---|---|
|ico_excellent.gif|◎|
|ico_perfect.gif|○|
|ico_great.gif|△|

未知の画像は勝手に○等へ変換せず取得失敗として記録する。
馬番だけでなく馬名・出走馬全体を照合し、アクセス拒否やログイン画面は成功にしない。

## 運用

通常15分間隔の収集は追加指定不要。既存Indexだけに追加列を入れる場合：

```sh
.venv314/bin/python umanity_collect_daily_uindex_and_results.py --index-extras-only --date 20261003 --tracks 05 --races 12 --headless --no-run-norikae
```

このモードではResults・予測・購入を実行しない。既存の日別Mergedがあれば追加列だけ更新する。
`--refresh-index-extras` で血統・調教も再取得する。
`--no-index-extras` は通常収集への追加取得を止める指定で、過去の有効な追加列は消さない。
`--races` は部分上書きを避けるため `--index-extras-only` 専用。

夜間は `夜間_追加データ収集.command` をダブルクリックするか：

```sh
.venv314/bin/python collect_umanity_supplemental.py --background --not-before 21:00 --dates 20261003,20261004
```

既存Indexがある日だけ対象。通常収集とロックを共有し、最大10分待機する。
ログは `logs/night_collection_*.log`、取得状況は `logs/night_collection_manifest_YYYYMMDD.json`。
夜間収集の起動そのものは別途必要。コード更新だけではジョブを起動しない。

## 保存と予測への利用

既存の有効値は取得失敗時も保持する。馬名が変わった馬へ旧値を引き継がない。
発走前の値を発走後取得で上書きしない。
空・重複・既存出走馬が欠けるIndexを拒否し、CSV読み戻し後に原子的に置換。
自動バックアップは作らない。CSV読み戻しと原子的な置換は維持する。
2026-10-03に、旧IndexExtras101ファイル・旧自動バックアップ6ファイルを整理した。
血統・厩舎評価の未反映値はIndexへ移し、旧調教の不正確なスライス値は移行しない。

東京12R、および過去4レースの調教サンプルは発走後取得のため、発走前取得=0。
過去4レース64頭の実ページでは、旧解析で16頭だった1F時計が修正後63頭となった。
残り1頭は元ページに時計がない。これは収集カバー率で、予測の的中率ではない。
過去レースを今取り直したデータを、当時の発走前データと偽って検証しない。
現時点では追加列の収集・保存のみで、予測の重みや印を変更していない。
新因子の精度改善は、発走前データを蓄積して時系列分割で別途確認する。
