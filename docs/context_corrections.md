# 2026-10-03 暫定補正の運用と検証

## 本番への反映範囲

通常予測コードに組み込み済み。補正の適用開始日は2026-10-04。
本番のPredict・master・Viewer・購入予約をこの作業から直接書き換えていない。

市場入力の更新（actual-market-only-v7）: 「みんなの人気」を全予測経路から除外。モデル・基礎特徴・調整キャッシュと旧調整初期値は新入力方式と区別する。次回の通常予測で再学習・再計算が必要で、既存Predictを自動で一括書換えしてはいない。旧入力方式でしか検証されていない紐校正・場別設定は、モデル方式の一致ガードにより新モデルでは適用保留となる。脚質の多数決方式そのものは維持する。

最新の出力・収益性修正は `actual-market-profitability-v8`。最終順位での勝負判定、期待値用勝率のレース内正規化、収益候補の別列診断と購入側の任意AND条件を追加。市場学習入力はv7と同じため、v17のモデルキャッシュは維持する。比較と採用状況は [収益性改修](profitability_selector.md) を参照。

- 場別紐補正：**京都・ダート・1800mの既存監視候補だけ**をユーザー指定で暫定適用する。因子は前型票率×内枠度。その他19条件は比較候補のみで、印は変えない。
- 実人気変動：最新の実人気4～6位で、発走約1時間前より人気が上昇した馬を紐候補として加点する。◎○は固定。みんなの人気・予想家予測・確定オッズは使わない。
- 開催序盤：開催1・2日目、同じ競馬場×芝ダ×距離について、予測前型票率に比例して「平均差＋1日間標準偏差」を加点する。印にかかわらず対象。風向きの効果として加点しない。
- 新馬戦：架空の脚質・位置・展開適性を学習と当日計算の両方で中立化する。脚質票を0とし、脚質による紐校正・場別前型補正・開催序盤補正を除外する。結果の通過順は消さない。表示脚質は「予測対象外」、予測4C位置・内外は空欄とする。

中立値0.5はモデル入力のプレースホルダーで、「差し」や中団位置を予測した意味ではない。`脚質予測対象外=1`で識別できる。

## 設定・止め方

`config/venue_factor_correction.json`：20条件の因子・係数・強度を保存。
`experimental_enabled=true`は京都ダート1800mの1条件だけ。設定の実行環境・モデル方式と一致しない環境では適用しない。
全場別補正を止めるには`mode`を`shadow`へ変更する。京都だけを止めるにはその条件の`experimental_enabled`をfalseへ変更する。

`config/context_corrections.json`：市場補正と開催序盤補正を独立管理。

|項目|現在値|意味|
|---|---:|---|
|market.strength|0.30|実人気が2位以上上昇したときの最大加点|
|market.popularity_min / max|4 / 6|最新実人気の対象帯|
|market.baseline_minutes / baseline_max_minutes|60 / 80|発走60～80分前の最新スナップショットを基準|
|market.cutoff_minutes|5|発走5分前より後の取得は使わない|
|market.max_age_minutes|15|判定時点の取得期限。発走直前では最大20分前|
|opening.sigma_multiplier|1.0|日間標準偏差の倍率。推定の信頼区間ではない|
|opening.max_delta|0.30|開催序盤補正の上限|
|opening.minimum_days|20|条件別の最低序盤開催日数|

各層を止めるには`market.enabled`または`opening.enabled`をfalseにする。
全追加補正を候補表示だけにするには`mode=shadow`。本番適用には`user_authorized=true`も必要。
取得履歴不足・古いオッズ・取得元混在・出走馬集合不一致・発走済みでは市場加点を0とする。
当日の結果を見た後に過去の市場補正を捏造しない。

`config/opening_front_prior.json`は2021～2024の保存済み**予測脚質票**から作った41条件の事前設定。
開催序盤の前型群と後型群の3着内率差から、同条件の3日目以降の平均差を差し引く。
平均＋1σはユーザー指定の強め設定であり、精度改善が確認された最適係数ではない。
結果脚質を予測入力として利用しない。

## 夜間の追加ページ収集

`夜間_追加データ収集.command`をダブルクリックする。
起動日の今日・翌日のレースを対象に、21:00 JSTまでは待機し、その後1回収集する。21時以降の起動なら直ちに開始する。
バックグラウンド実行で、ログ・PIDを`logs/night_collection_*.log`・`logs/night_collection.pid`に保存する。
通常コレクトと同じロックを利用し、最大10分待つ。ロックは奪わない。収集開始後は待機を含め最大2時間、レース間1.5秒。

現行は、通常コレクトと同じ仕組みで血統・厩舎評価・調教の実リンクをたどり、既存Index/Mergedへ30列を追加する。
血統・調教は同一レースの取得成功後に再取得しない。実オッズは通常コレクトが担当する。
既存のUmanityログインと権限を利用する。VIP制限は回避せず、アクセス拒否画面も取得成功にしない。
東京12Rの実取得とIndex/Mergedへの反映は確認済み。**全場一括の夜間収集ジョブはまだ起動していない。**

追加データはIndex/MergedのCSVだけに保存する。IndexExtras・自動バックアップは作らない。
Indexの取得済み値を再利用し、取得時刻・取得URL・発走前かもCSVに記録する。
現在のmasterや過去予測はこの追加列更新では上書きしない。以前のレースを今から取り直したページを、当時の発走前情報として学習させない。
