# 平場の購入モデル v2

2026-10-04、ユーザーの書き換え指示により平場の既定モードをRへ変更。
性能保証ではなく、検証を続けるための暫定採用。実購入・サーバー再起動・保存済みの手動モード変更は行っていない。

## 現在の分岐

|出走頭数・条件|買い方|点数・予算|
|---|---|---|
|5頭以下の平場|見送り。手動モード指定でも購入しない|0円|
|6〜9頭|採用順位1位を1着固定、相手4頭の3連単|12点・1,200円|
|10頭以上|軸を固定しない上位候補5頭の3連複BOX|10点・1,200円|
|10頭以上でも突出軸条件が成立|相手4頭の3連単|12点・1,200円|

重賞B/K・障害・新馬の既存方式は維持。既に保存されたA等の手動指定も維持するため、
そのレースはRへ自動変更されない。新馬は従来の自動選択除外設定を維持。

突出軸条件は、軸のU指数が他馬の最高値を5以上上回る、軸のML勝率が首位、
レース内正規化後の勝率シェア35%以上のすべて。正規化は確率校正ではない。
今回の検証データで成立例がなかったため、この例外分岐の実績は未検証。

候補馬は購入直前のViewerの印・採用順位に合わせる。通常印を持たない飛印馬は
買い目候補から除外するが、実際の出走頭数や競合馬の強さには含める。
従来の○・▲の乗り替わり優先、▲爆の次順位という規則も共通選択器で維持。

予算は100円単位で固定する。5頭BOXは全10通り各100円に、候補順位の高い
2通りへ100円ずつ追加する。的中結果・確定オッズによる配分ではない。
券種は混在させず、必要候補不足・重複・不正順位・古いViewerは安全に停止する。

## 設定・構成

- `config/flat_purchase_policy.json`: 本番Rの明示設定。現在は`axis4 / box5 / strict / confidence=0`、1,200円。
- `flat_race_ticket_selector.py`: 検証と購入で共通の券種・組合せ生成。旧Rの混合券種計算は削除。
- `purchase_system/src/keiba_purchase/data_view.py`: 最新Viewerから買い目作成、点数・予算・設定ハッシュを記録。
- `purchase_system/src/keiba_purchase/automation.py`: 見送りはPATへ進めない。購入直前にCSV・Viewer・購入設定・選択器コードの変更を検知する。
- `purchase_system/ui/app.js`: Rの実際の券種・買い方・点数・金額・見送り理由を表示。

長時間起動している購入サーバーはPythonコードを保持する。変更後は通常の方法で
購入サーバーを再起動する必要がある。コードの新旧混在を検知した場合は買い目生成を停止する。
設定ファイルは買い目作成時に読む。検証出力の`candidate_policy.json`を自動採用する経路はない。

### 稼働中プロセスへの反映確認（2026-10-04）

保存コード・設定は新方式だが、購入画面と購入監視の常駐プロセスは旧コードのまま。
購入画面の`/api/races?date=20261004`を読み取り確認したところ、
旧モードC/M/A等が返り、新方式Rは返らなかった。
購入画面は10/2 22:06:21、購入監視は10/3 09:38:41起動（いずれもJST）、
今回の変更は10/4 08:54までに保存されており、起動順も整合する。
一方、新しいコードを別プロセスで読み取り検証すると当日の平場R15レースを生成できた。

実購入が有効な状態なので、この確認では常駐プロセスの再起動・購入設定変更・購入を行っていない。
新方式を稼働側へ反映するには、購入画面と購入監視の両方を承認後に再起動し、
当日APIの券種・点数・金額と新コードでの計画が一致することを確認する必要がある。
「コード更新済み」と「自動購入へ反映済み」は区別する。

絶対ML確率での足切りは本番では無効。保存Predictの軸3着内値中央値88.6%に対し、
今日の現行モデルは56.6%で、旧モデルの60%等をそのまま適用できない。
本番設定に非ゼロの`confidence`を入れた場合は、再校正なしの誤適用を防ぐため停止する。

## 同一予算の比較結果

保存Predictと日別Resultsで完全な平場867レースを照合。6〜7月を探索、8月を選定、
9/1〜10/3を比較期間にした。構造63候補を比較し、6〜7月・8月とも的中率20%以上、
40レース以上、10的中以上、参加率30%以上を要求し、両期間回収率の低い方を最大化。
この条件では5頭BOXが残った。ただし9月までのデータは以前の比較にも使っており、
完全に未使用の将来検証ではない。

3連複へ分岐する共通161レース、すべて1レース1,200円で比較:

|3連複の買い方|的中率|回収率|
|---|---:|---:|
|4頭BOX|11.18%|109.19%|
|軸なし5頭BOX・暫定採用|22.36%|90.05%|
|1頭軸・相手5頭|24.22%|56.29%|
|2頭軸・相手最大12頭|19.88%|89.77%|
|上位3頭中心12点|22.36%|83.41%|
|軸なし上位4頭中心12点|24.84%|76.97%|
|U指数差で1軸・2軸・軸なし切替|24.22%|75.42%|

4頭BOXはこの期間のみ回収率が高いが、6〜7月・8月の的中率条件を満たさない。
2頭軸の一律適用や条件切替も、5頭BOXを安定して上回らなかった。
候補実装は残してあり、設定と比較ツールで再検証できる。最高・最適であるという主張ではない。

券種分岐全体の同じ186レース、双方223,200円の比較:

|方式|的中数・的中率|払戻|回収率|収支|
|---|---:|---:|---:|---:|
|旧モード規則を再現・予算正規化|25 / 13.44%|125,350円|56.16%|-97,850円|
|新分岐・5頭BOX|43 / 23.12%|191,140円|85.64%|-32,060円|

新方式の回収率の日別ブートストラップ95%区間は55.04〜117.15%。
最大払戻を除くと71.28%。まだ利益が安定して出るという証拠ではない。
6〜9頭側25レースの3連単回収率は57.23%で、次の改善優先候補。

### 3連単の追加見直し（2026-10-04）

同じ3連単分岐対象の104レース（6〜7月50、8月29、9/1〜10/3の25）を、
各レース1,200円で比較。今回は突出軸例外の成立例がないため、対象はすべて6〜9頭。

|買い方|6〜7月 回収率|8月 回収率|9/1〜10/3 回収率|9/1〜10/3 的中率|
|---|---:|---:|---:|---:|
|現行：1位を1着固定、相手4頭・12点各100円|95.32%|83.71%|57.23%|28%（7/25）|
|候補：1着は上位2頭／2着は上位3頭／3着は上位5頭・12点各100円|67.60%|82.10%|110.87%|28%（7/25）|
|候補：上位3頭BOX・6点各200円|45.73%|11.55%|136.47%|16%（4/25）|

上位2頭候補は直近で払戻17,170円→33,260円と改善したが、探索・選定の両期間では悪化。
3頭BOXは直近回収率が高い一方、的中率と前期間の成績が大きく悪化する。
直近の最大払戻を除いた回収率は上位2頭68.67%、3頭BOX52.07%。
25レースの結果だけで本番採用せず、3連単設定は現行`axis4`を維持する。
上位2頭は次の未使用期間で比較する候補とする。利益や最適性を保証する結果ではない。

既存比較ツールに`trifecta_shape_comparisons_same_routed_races`を追加し、
分岐対象を変えずに3方式の期間別成績を毎回出力する。
`outputs/flat_trifecta_review_20261004/report.json`に結果を保存。
全104レース×3方式の組合せ・着順一致・予算・払戻を別計算で照合済み。
追加テストを含む関連33テストはPython3.14と3.10で通過。
本節も保存Predictの再試算であり、以下のモデル来歴・期間再利用等の限界は同じ。

重要な限界:

- 848レースはモデル来歴不明、19レースは10/3のv6。今日のv8モデルの独立検証ではない。
- 保存印の再試算であり、実購入履歴・購入時Viewerの再現ではない。自動購入対象だけでなく完全な平場も含む。
- 学習時点不明のPredictは、日付分割だけで学習リークがないとは証明できない。
- 単勝・券別の購入時オッズを使っていないため、券別EVによる購入モデルではない。
- 取消・同着・不完全レースは除外。欠損は外れ・ゼロとみなしていない。
- 芝/ダート・距離・競馬場ごとの少数スライスをこの比較だけで自動最適化していない。

比較結果は`outputs/flat_ticket_multi_axis_20261004_release/`。
867レースの全買い目について、Resultsの着順と払戻から別計算し、金額・重複・的中・収支の一致を確認。
レポートには入力ファイルとコードのハッシュ、モデル別集計を記録している。

## 動作検証と次の課題

関連45テストはPython3.14/3.10双方で合格。今日の24レースの計画を読み取り検証し、
平場R15レース（3連単2・3連複13）、重賞B2、新馬の旧方式7が生成できた。
実購入・自動購入の有効化・サーバー再起動はしていない。UIは構文・テンプレートを検証、
スマホ実機の操作確認はしていない。
全242テストでは236成功。既存の過去Viewer依存5件と、保存予測の固定馬番期待値1件が不一致で残る。

次は現行モデルを固定した未使用期間で、少頭数の1着固定対上位2頭・BOX、
