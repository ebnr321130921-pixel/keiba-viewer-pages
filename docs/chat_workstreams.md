# チャット分担と引継ぎ

共通ルールはプロジェクト直下の [AGENTS.md](../AGENTS.md)。同じKeibaプロジェクトでチャットを作り、以下の開始文のどれかを使う。
この資料は2026-10-11時点の引継ぎ。実行環境・設定・ファイル版は作業開始時に必要な範囲で再確認する。

## 1. 予測モデル・補正・血統

```text
AGENTS.mdとdocs/chat_workstreams.mdを読み、予測モデル・補正・血統を担当してください。
基礎能力と各補正を分け、未来情報や過剰学習がないかを時系列で検証してください。
買い目や購入サーバーには今回の目的に必要な範囲だけ触れてください。
```

主な対象は `keiba_predict_tool.py`、各補正、過去成績集計、学習特徴量、モデル履歴。
現行エンジンのML特徴量の明示的なリストには父・母父が含まれていない。独立した次期エンジン `analysis_engine/` は父・母父の過去成績と当日の条件相性を分けて実装し、線形・ブースティング・固定平均を基礎だけ／補正ありで比較する。
最初の候補は父・母父それぞれの芝/ダート・距離帯への適性。父×母父×競馬場×正確な距離を最初から直接係数にしない。
今回の細分化例では2025年の32,029組の98.54%が5出走未満で、中央値1出走だった。

関連：[予測メソッド](prediction_method_review.md)、[データ基盤の実測・提案](data_backend_evaluation_20261011.md)。

次期エンジン：[実行コマンドと境界](../analysis_engine/README.md)、[工程2〜6の設計](separated_engine_design_20261011.md)、[初回結果](../outputs/separated_engine_lab_20261011/README.md)。本番採用なし。Bakenは2026年分だけを2026年の平地重賞へ結合し、サイトなしでも基礎予測が変わらない独立データとする。

## 2. 買い目・レース選別・回収率

```text
AGENTS.mdとdocs/chat_workstreams.mdを読み、買い目・レース選別・回収率を担当してください。
まずoutputs/small_field_roi_validation_20261011/README.mdの比較結果を確認し、
現在のAuto Rと購入対象の選別を、投資額・的中率・回収率・収支で検証してください。
実購入と最終CSVの理論再現を分け、全レース購入は前提にしないでください。
```

主な対象は `flat_race_ticket_selector.py`、選別モジュール、`Kaime.py`、重賞Hybrid、`purchase_system/analysis/`。
平地重賞のHybrid、○を軸とする考え方、意図的な重ね買いを維持する。
凄馬・乗り換えは現行の分岐を確認して扱い、爆だけの自動軸昇格は採用しない。

直近の検証はモデル版 `2026-10-10.past-only-feature-audit-v10`、2021〜2026-10-10の保存済み620日。
**「少頭数・信頼軸」を理由に購入対象を追加する効果は安定していなかった。**

|最新Predictの評価で選別・2024〜2026|購入数|的中率|回収率|収支|
|---|---:|---:|---:|---:|
|従来選別・従来買い目|2,909|21.31%|88.04%|-417,650円|
|従来選別・現在買い目|2,864|21.33%|93.55%|-224,100円|
|少頭数選別も追加・現在買い目|3,248|20.14%|92.74%|-285,800円|
|追加対象のみ|384|11.20%|86.61%|-61,700円|

2024年の追加分は142.67%だが2025年52.27%、2026年58.13%。頭数だけで儲かる対象と判断しない。
保存済みViewerおすすめランクを優先すると、同期間の現在買い目は追加前87.42%、追加後87.52%。追加分は88.44%、50,220円の赤字。
この差には再予測より古いRecommend評価が関係している。Viewerの過去印変更までは再現できていない。
重賞Hybrid、当日残高上限、実際の発注、購入直前のオッズ変動はこの比較の対象外。
2024〜2026年は既に調べた期間であり、未使用の検証期間と呼ばない。

今回の分析は購入設定を変更していない。京都2Rの予約・少頭数条件の反映は前の作業で行われたもので、今日の予約状況は別途確認する。
資料：[詳細レポート](../outputs/small_field_roi_validation_20261011/README.md)、[年別数値](../outputs/small_field_roi_validation_20261011/metrics.csv)、[入力と買い目](../outputs/small_field_roi_validation_20261011/race_comparison.csv)。

## 3. 購入運用・Viewer

```text
AGENTS.mdとdocs/chat_workstreams.mdを読み、購入運用・Viewerを担当してください。
最初に現在のパネル・監視状態・予約と当日Predict/Viewerの整合性を確認してください。
既存の自動購入を維持し、診断で投票せず、必要な修正と動作確認まで進めてください。
```

主な対象は `purchase_system/src/keiba_purchase/`、UI、`Viwer_EDIT.py`、`Keiba_Sim.py`。
入口は `操作用/panel_runtime.command`。パネルと監視は別プロセスで、稼働済みサーバーを再利用する。
2026-10-11確認時の購入設定は7分前、再確認3秒。数値は設定ファイルが正本。
最新印で予約を再構築し、購入済みと成立未確認の再送を避ける既存経路を維持する。
古い `purchase_system/README.md` には3.10のPythonパス、5分前・20秒監視、旧B/Kの説明などが残る。そこだけを根拠に設定・購入ロジックを巻き戻さない。
UIに表示されたプレビューと、フルAutoの選択・予約対象を区別して確認する。

## 4. 収集・Parquet・DuckDB・処理効率

```text
AGENTS.md、docs/chat_workstreams.md、docs/data_backend_evaluation_20261011.mdを読み、
収集・データ基盤・処理効率を担当してください。
既存CSVを保ちながら、分析用ParquetとDuckDBの導入を進めてください。
キー・型・欠損・件数・集計の一致を検証し、学習や購入への反映は別に検証してください。
```

通常のPythonは既に3.14.4。DuckDB 1.5.6は分析専用 `analysis_engine/.deps` に導入した。本番 `.venv314` のライブラリを変更していない。旧ベンチマーク用の隔離環境も残している。
2025年の血統集計はCSV+pandas約1.97秒、CSV+DuckDB約0.67秒、9列Parquet+DuckDB約0.009秒。
元データ309,490行の投影9列の値と、3回の集計結果は一致。これは予測・学習全体の速度や精度の比較ではない。
次はスキーマ・取得時刻・モデル版を持つ分析用データの増分更新と、過去時点での特徴量集計。
年別再計算の学習キャッシュ保持方法も確認する。現在の共有モデルキャッシュは新しい3件を残すため、複数年の並行処理で再学習を増やす可能性がある。現時点では可能性であり、実ジョブでの影響は未測定。

## チャット間の引継ぎ

異なるチャットは会話の続きや稼働状態を自動共有すると仮定しない。ファイルで引き継ぐ。
同じファイルへの変更を並行させず、当日のPredict、モデル版、共有設定、サーバー操作は担当を一つにする。
独立した読み取り分析はそれぞれ別の `outputs/` 配下で実行できる。
長い作業を終えるときは必要に応じて `docs/handoffs/<担当名>.md` に次を残す。短い資料修正では不要。

```text
更新日時：
担当・目的：
変更ファイル：
使用したデータ・モデル版：
実行コマンド・結果フォルダ：
検証結果・制約：
本番への反映と稼働状況（確認時刻付き）：
未解決点・次の作業：
```

秘密情報、Cookie、認証値は引継ぎに含めない。過去のPIDや予約数は現在の状態として使わない。
